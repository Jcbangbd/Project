# 智慧港口 VR：本地实施记录

本记录对应用户批准的 `修改方案.md`。方案文件记录的是设计阶段的状态；本记录和 `ImplementedScreenshots/` 才是本次实施结果。截图由 Unity 原生 uGUI/TMP 渲染，不是生成的界面效果图。

## 已完成内容

1. 登录页使用明亮科幻港口背景和浅色 Sci-Fi 登录组件，保留原账号、密码、登录、密码修改、状态提示及加载逻辑。实际登录场景为 `Assets/Scenes/2.unity`，方案中写作 SceneEntrance 的位置已在实施时核实；无需更换原登录入口。
2. 新建浅色全屏实验介绍 Canvas：五个流程标签、原有流程图及文字、流程图放大、学习模式和仿真决策入口。学校圆形标识及机构文字不再显示；旧对象和图片资源保留，避免破坏其他引用。
3. 第1题从教师完整算例中按作业类型分组，卸船、装船、卸车、装车、翻箱各抽一条，打乱顺序；一次作答中返回上一题不重新抽样。放大表格和下拉文字，删除无关的“岸桥”列。选择任一行后，在表格下方展示所选类型的流程图和完整说明，不提示答案是否正确；可放大图片、滚动说明。
4. 卸船仿真实验取消“岸桥设置”按钮和必须先勾选岸桥的门槛，自动分配真实源箱和岸桥。原资源保留，其他实验的既有设置入口不批量删除。
5. 算法计算改用独立浅色 Sci-Fi 遮罩：所选算法、任务数量、旋转指示、真实阶段和已用时，不显示假百分比。失败时关闭计算态并提供错误信息及重试入口。
6. 修正新介绍 Canvas 离开菜单、返回介绍、重新打开主菜单时的显隐；进入答题仍关闭算例页面，避免两个页面叠放。

整套准备答题仍为 **8题**，仅第1题的算例行数改为5条。五条全部正确得5分，任一错误或漏选得0分；总分上限仍为100分。正式算例缺少任何一种类型时，明确提示缺少类型，并允许返回重新获取，不编造正式任务。

## 算法与岸桥的实际边界

保持：完成答题 → 三维预览 → 选择算法 → 选择原因 → 填参数 → 只执行所选算法 → 调度核对 → 推演。没有默认选遗传算法，也没有额外依次执行三个算法。

**没有修改或替换现有 GA/PSO/ALNS EXE。** 原 EXE 输出仍是场桥/RMG 调度。新增 Unity 岸桥分配阶段按实际可用设备、各岸桥源箱容量和运输距离，采用“预计最早完成”启发式分配；它是独立资源分配算法，不是对原 EXE 的岸桥—场桥联合优化扩展，也不保证全局最优。

- 自动分配不读取隐藏勾选页的 Toggle 状态；直接核实船舶源箱，先上层后下层，检查源箱重复和容量不足。
- 动画逐条消费相同任务的源箱、目标箱位、岸桥编号；不再把固定的岸桥—箱区对应关系用作自动岸桥选择。
- `ScheduledOperationDto.craneId` 保留原场桥含义；新增 `quayCraneId`、`sourceVessel`、`sourceShipBay/Column/Tier`。
- 报告新增 `quayAssignmentMethod` 和 `quayAssignments`，记录任务编号、顺序、岸桥、场桥、源箱及目标。调度指纹也覆盖新增字段。
- 源箱不足、岸桥不可用、目标路线不受支持等情况会阻止启动并显示错误，而不是静默漏掉任务。
- 当前可执行的自动卸船堆场路线仍限于项目已有 A35/A36/A37/A40，未虚构其他箱区的设备路径。

这次只修改客户端数据模型与流程，没有部署或修改远程接口；服务端如需保存新增岸桥字段，需要同步接受这些扩展。原成绩本地保存入口仍为 `StudentAssessmentRuntime.SaveAndSubmit()`，文件位于 `Application.persistentDataPath/AssessmentRecords/<任务ID>_<时间>.json`，随后调用既有提交网关。
